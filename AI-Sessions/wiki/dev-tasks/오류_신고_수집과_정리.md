# 오류 신고 수집과 정리

## Summary

각 앱(관제·하위보카·태블릿 하위사전)에 **오류 신고 버튼**을 달아, 사용자가 한 줄만 적으면 재현에 필요한 정보가 자동으로 붙어 관제 신고함으로 모인다. 신고 원문은 옵시디언 `raw/신고함/`에 달마다 쌓이고, 분류·원인 추정·수정 제안은 이 폴더(`wiki/dev-tasks/`)에 별도 문서로 만든다.

**왜 만들었나**: 본사 러닝 스튜디오 베타를 쓰며 "캡처 뜨고 계정·기기 적어서 보내 달라"는 요청이 현장에서 지켜지지 않는 걸 확인했다. 신고에 드는 수고가 조금만 있어도 신고는 안 올라오고, 불편은 그대로 남는다. 우리 앱부터 그 수고를 0으로 만든다.

## Context

- 제안자·결정: 원장 (2026-08-25)
- 화면 캡처는 **일부러 넣지 않았다**. 브라우저가 '화면 공유' 승인 팝업을 띄워 그 자리에서 이탈이 나고, 실제 재현에는 캡처보다 아래 기록이 쓸모 있다. (근거: 러닝 스튜디오 등록이 막혔을 때 화면은 완전히 정상이었고 원인은 네트워크 기록 한 줄 `ERR_BLOCKED_BY_CLIENT`에 있었다.)
- 같은 아이디어를 본사에도 건의했다 → `C:\모의고사자동화\본사건의_러닝스튜디오_오류신고버튼.md`

### 자동으로 붙는 것 (사용자는 한 줄만 적는다)

| 항목 | 쓰임 |

| 앱·버전·화면 이름·주소 | 어느 배포본의 어느 화면인지 |

### 정리 루틴 (에이전트가 하는 일)

원장이 "신고 정리해줘"라고 하면:

1. `raw/신고함/`의 새 신고를 읽는다 (raw는 **고치지 않는다**).
2. 묶는다 — 같은 원인으로 보이는 신고를 하나로. 건수가 곧 우선순위다.
3. 나눈다 — ① 진짜 버그 ② 기능 요청 ③ 사용법 오해(→ 화면 문구를 고칠 일) ④ 기기·인터넷 문제.
4. 각 묶음에 **원인 추정 + 고칠 파일/함수 + 예상 난이도**를 적는다.
5. `wiki/dev-tasks/신고정리_YYYY-MM-DD.md`로 저장하고, 원장에게는 **"고치자/두자"를 고를 수 있는 목록**으로 보고한다. 판단은 원장이 한다.
6. 고친 뒤 신고함에서 해당 건을 '처리'로 바꾼다.

③ 사용법 오해가 반복되면 코드가 아니라 **문구**를 고친다. 같은 오해가 3번 나오면 그건 사용자 잘못이 아니다.

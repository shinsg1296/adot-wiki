# 관제 재작성 인수 조건 (AC)

## Summary

관제를 새 그릇(DB 기반)으로 다시 만들 때 **"통과해야 끝난 것"의 목록**이다. 기능 명세가 아니라 **회귀 방지 명세** — 이미 겪은 사고를 새 시스템에서 다시 밟지 않는다는 조건이다. 근거는 전부 `wiki/errors/` 실제 사고이며 추측으로 만든 항목은 없다.

**쓰는 법**: 화면 하나를 새로 옮길 때마다 해당 AC를 체크한다. 전부 통과하지 못한 화면은 옛 경로를 유지한다.

⚠️ 이 문서는 **재작성을 하기로 결정했다는 뜻이 아니다.** 착수 여부는 원장 판단이며, 이 문서는 판단에 필요한 조건을 미리 고정해 둔 것이다. (status: draft)

## Context

### 왜 필요한가
관제는 `index.html` 단일 파일 + Python 서버 + JSON 파일 데이터로 자라왔다. `errors/` 10건을 원인별로 묶으면 **개별 실수가 아니라 같은 구조가 반복**된다.

| 반복되는 구조 | 사고 횟수 |
|---|---|
| 같은 사실이 두 곳에 저장됨 | 3회 (근태 8/12 · 정답키 8/19 · seatLayout 3화면 8/20) |
| 키가 이름 기반이라 동명이인 충돌 | 2회 (숙제 8/13 · 성적 ~8/18) |
| 부분·빈 데이터가 전체를 덮어씀 | 2회 (명단 0명 8/11 · 등원이력 유실 8/12) |
| 판정 로직이 경계값에서 뒤집힘 | 2회 (센티널 0 · 복귀 타이밍) |
| 쓰기 성공을 확인하지 않음 | 2회 (타임아웃 오탐 · sendBeacon 유실) |

**같은 패턴이 3번 나온 항목이 있다**(기록 두 곳). 이건 주의력 문제가 아니라 구조 문제이므로, 구조를 바꾸지 않으면 4번째가 온다.

### 이미 확정된 설계 결정 (바꾸지 않는다)
- **지점 격리 = 인스턴스 분리.** 멀티테넌트 기각 — "버그 하나가 타 학원 정보 노출"(원장, 2026-08-19). 따라서 아래 AC에서 지점 간 격리는 **DB 행 필터가 아니라 인스턴스 경계**로 보장한다. 행 단위 권한(RLS 등)은 **한 지점 안의 역할 격리**(원장/강사/조교)에만 쓴다.
- **지점종속값은 `branch.json` 하나로.** 설정이 없으면 화면이 스스로 멈춘다(옛값 복귀 금지).
- **계정이 지점을 결정한다.** 로그인·세션·명단API·명단파일 4경로 차단 검증 완료.

## A. 데이터 정합성 — 키와 단일 출처

| ID | 인수 조건 | 확인 방법 | 원 사고 |
|---|---|---|---|
| **AC-01** | 학생을 이름으로 조회하는 코드 경로가 **0개**다. 모든 조회는 학생 ID(PK)로만 한다. | 동명이인 2명에게 서로 다른 숙제·성적·프로필을 넣고, 카드·모달·출결행·검색 **모든 진입 경로**에서 각자 것만 보이는지 확인 | 김민성 2명 프로필 공유 · 숙제 교차 · 성적 미분리 |
| **AC-02** | 같은 사실을 저장하는 곳이 **두 곳 이상이면 배포하지 않는다.** 불가피하면 어느 쪽이 정본인지 문서에 적고, 읽는 쪽이 반드시 합친다. | 새 저장 경로를 추가할 때 "이 기록을 읽는 화면이 다른 파일도 보고 있나"를 점검 항목으로 강제 | 근태 2파일 · 정답키 로컬vs시트 · 좌석 3화면 |
| **AC-03** | 같은 것을 그리는 화면이 여러 벌이면 **정의는 한 벌**을 본다. | 좌석 배치를 한 곳에서 바꾸고 관제·TV·아이패드 3화면이 동시에 바뀌는지 확인 | 대구에 일곡 17석이 그려짐 |
| **AC-04** | 목록·집합의 정의가 두 벌 존재하지 않는다(동명이인 목록 등). | 정의가 되는 상수·테이블을 grep 해 중복 선언 0건 | `DUP_NAMES`/`DUPNAMES` 두 벌 |

## B. 쓰기 안전 — 덮어쓰기와 유실

| ID | 인수 조건 | 확인 방법 | 원 사고 |
|---|---|---|---|
| **AC-05** | **부분 데이터가 전체를 덮어쓸 수 없다.** 동기화·미러·내보내기는 전체를 볼 수 있는 주체만 실행한다. | 권한이 제한된 계정으로 로그인해 모든 화면을 열어도 원본 건수가 줄지 않는지 확인 | 조교 계정이 학생 0명을 VPS에 push → 자습실 전원 소실 |
| **AC-06** | **읽기에 실패하면 쓰지 않는다.** 빈 값을 정상 상태로 간주해 저장하는 경로가 없다. | 원본 파일/테이블을 일시적으로 못 읽게 만들고, 그 상태로 저장을 시도해 기존 기록이 남는지 확인 | 등원 이력 7월~8/9 **영구 유실** |
| **AC-07** | 모든 쓰기는 **멱등 키**를 가진다. 같은 요청을 두 번 보내도 기록은 한 줄이다. | 같은 요청을 연속 2회 전송해 `dup` 처리되는지 확인 | 숙제 중복 배정 위험 · 단어시험 재전송 |
| **AC-08** | **쓰기 타임아웃을 실패로 단정하지 않는다.** 서버를 재조회해 확인한 뒤에 실패를 말한다. | 서버 응답을 인위적으로 지연시켜, 저장은 됐는데 "실패"가 뜨지 않는지 확인 | "배정 실패 2건" 오탐 |
| **AC-09** | 새 저장 경로는 **① 응답 확인 ② 실패 시 재시도 ③ 실패를 사람이 볼 수 있게** 셋을 모두 갖춘다. 던지고 잊는(fire-and-forget) 전송 0건. | 네트워크를 끊은 상태로 저장 → 미전송 표시가 뜨고, 복구 시 자동 재전송되는지 확인 | 박조영 단어시험 조용한 유실 |

## C. 권한

| ID | 인수 조건 | 확인 방법 | 원 사고 |
|---|---|---|---|
| **AC-10** | 권한은 **화면이 아니라 데이터 계층**에 있다. 주소를 직접 쳐도 권한 밖 데이터가 응답에 담기지 않는다. | 조교 계정으로 원장 전용 API 주소를 직접 호출해 403 또는 빈 응답인지 확인 | "화면만 숨기면 주소로 우회된다" |
| **AC-11** | 권한으로 거른 데이터를 **다른 곳에 쓰는 경로도 함께 막혀 있다**(동기화·미러·내보내기·집계). | 제한 계정으로 모든 화면을 순회한 뒤 원본 건수 대조 | AC-05와 동일 사고 |
| **AC-12** | 첫 렌더 **이전에** 권한이 확정된다. 권한 밖 화면이 1초라도 보이지 않는다. | 느린 회선에서 조교 계정 로그인 → 원장 화면 깜빡임 0 | `/api/me`를 나중에 물어 원장 화면 1초 노출 |
| **AC-13** | 계정 종료는 **삭제가 아니라 비활성**이다(기록 보존, 로그인만 거부). | 종료된 계정의 과거 근태·작업 기록이 그대로 조회되는지 확인 | `disabled:true` 정책 |
| **AC-14** | 개인정보(연락처)는 **요청한 한 건만** 응답하고, **열람 로그**를 남긴다. 명단·프로필에는 포함하지 않는다. | 명단 API 응답에 번호가 없는지 + 열람 로그가 쌓이는지 확인 | `_contacts.json` 설계 |

## 재작성으로 자동 해소되는 것 vs 여전히 설계해야 하는 것

**DB(관계형) 도입만으로 구조적으로 사라지는 것 — 9건**
AC-01(PK) · AC-02(단일 테이블) · AC-04 · AC-05(조건부 UPDATE·FK) · AC-06(트랜잭션) · AC-07(unique 제약) · AC-10(행 단위 권한) · AC-13(soft delete) · AC-24(timestamptz)

→ `errors/`의 절반이 여기 해당한다. **재작성의 값어치는 화면이 아니라 이 9건**이다.

**DB를 써도 직접 설계해야 하는 것 — 나머지 21건**
판정 로직(D 전체) · 지점 분리(E 전체) · 외부 연동(G) · 운영(H) · UX(AC-18).

→ 특히 **D(판정 로직)는 원장님 운영 규칙 그 자체**라 어떤 프레임워크도 대신 해주지 않는다. 새로 만들 때 가장 많은 시간이 여기 들어가며, 여기가 곧 관제의 진짜 자산이다.

## 착수 전 선결 2건 (재작성 여부와 무관하게 지금 열려 있음)

1. **관제 소스 저장소 이관** — 현재 원장 PC와 VPS에만 존재. 재작성은 원본을 계속 참조하는 작업이므로 이 상태로 시작하면 안 된다. (하위보카는 이미 `shinsg1296/adot-word-app`로 운영 중 → 같은 방식)
2. **백업 오프사이트 회수** — 백업이 같은 서버에만 있어 VPS 소실 시 함께 사라진다.

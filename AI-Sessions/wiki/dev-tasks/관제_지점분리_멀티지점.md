# 관제를 여러 지점에서 쓰기 (지점 분리 · 계정이 지점을 정한다)

## Summary

일곡점 전용으로 만든 관제를 **다른 학원에도 쓰게** 하는 작업. 대구달서점이 첫 대상이고,
관계는 [[HAWE_사업설계]]의 **셋업 서비스 첫 고객**이다(원장 확정 2026-08-19).

그래서 설계 원칙이 하나 정해졌다 — **코드는 넘기지 않는다. 원장님 서버에서 돌리고 웹으로 쓰게 한다.**
상대는 계정으로 들어와 자기 지점만 본다.

## 1. 왜 인스턴스 분리인가 (멀티테넌트를 안 쓴 이유)

| 방식 | 채택 | 이유 |
|---|---|---|
| **인스턴스 분리** (폴더·도메인을 나눔) | ✅ | 데이터가 물리적으로 갈라져 **사고가 번지지 않는다** |
| 멀티테넌트 (한 서버에 지점 개념) | ✖ | 격리를 코드로 보장해야 함 → 버그 하나가 **다른 학원 학생 정보 노출** |

고객이 3곳쯤 되면 그때 전환한다. 지금은 폴더가 갈라진 쪽이 안전하다.
대신 코드를 고치면 두 곳에 배포해야 하므로 배포 스크립트로 묶는다.

```
hawecontrol.com          → /opt/adot-dash          (일곡점)
dalseo.hawecontrol.com   → /opt/adot-dash-dalseo   (대구달서점)
```

traefik이 Host 규칙으로 갈라주므로 도메인만 추가하면 된다.

## 2. 1단계 — 지점 설정 분리 (완료 2026-08-19)

지점에 묶인 값을 **`dashboard/branch.json` 한 파일**로 뺐다. 폴더를 복제하고 이 파일만 바꾸면 다른 학원이 된다.

빠져나온 것: 숙제·단어앱 시트 주소 · 접근 토큰 · 교사 계정과 표시 이름 · 반 이름과 반별 본사 담당 강사 ·
자습실 좌석 수 · 관제 주소 · **학교 지역 필터**(광주·전남 → 대구는 대구·경북).

- 서버가 화면에 `window.BRANCH`로 **심어서** 넘긴다. 화면 상수가 부팅 즉시 참조하므로 비동기로 받으면 늦다.
- **설정이 없으면 화면이 스스로 멈춘다.** 예전 값으로 조용히 되돌아가면 *대구 화면이 일곡점 시트에 쓰는* 사고가 난다.
- 서버도 `branch.json`이 없으면 기동을 거부한다.
- 반 id는 `sg`(원장반)·`jk`(강사반) 규약을 유지한다 — 권한표와 화면이 이 id를 쓴다.

템플릿은 `dashboard/branch.dalseo.json`(채울 칸에 `_채울것` 안내 포함).

## 3. 계정이 지점을 정한다 (완료 2026-08-19)

원장 지시: *"뭘로 로그인하느냐에 따라 다르게."* 계정마다 `branch`를 달고, **어느 주소로 들어와도 계정이 지점을 결정**한다.

막는 지점이 네 곳이다(전부 실제로 시험해 확인).

| 경로 | 결과 |
|---|---|
| 다른 지점 계정으로 로그인 | 그 지점 주소를 돌려주고 이동 |
| 세션을 들고 남의 지점 화면 열기 | 302로 되돌림 |
| 명단 API 직접 호출 | 403 `wrongBranch` |
| 명단 파일 직접 받기 | 빈 응답 |

- 지점 목록은 `_branches.json`. 파일이 바뀌면 다시 읽으므로 **재시작이 필요 없다.**
- `SHARED_DIR`을 주면 계정·세션키를 지점끼리 공유해 한 번의 로그인으로 오간다(선택). 안 주면 완전히 따로 돈다.
- 지점이 하나뿐이면 이 값들이 비어 있어 **예전과 똑같이 동작한다.**

## 3-2. 실제 셋업 (2026-08-20 · 대구달서점 가동)

**한 주소로 들어와 계정이 지점을 정한다.** 처음엔 다른 지점 계정이면 그 지점 주소로 302로 보냈는데,
원장이 *"이 사이트로 안 넘어오게"* 라고 해서 **서버 안에서 넘겨받는 방식**으로 바꿨다.
`_branches.json`에 `internal`(같은 도커망 주소)이 있으면 302 대신 그 지점 관제로 요청을 넘기고
받은 그대로 돌려준다. 브라우저는 주소가 바뀐 걸 모르고, 데이터는 여전히 폴더째 갈라져 있다.

세션키를 지점끼리 공유하므로 로그인도 한 번만 한다(1분짜리 sso 표 → 주소에 남기지 않고 쿠키 발급).

**대구달서점 구성**

| 항목 | 값 |
|---|---|
| 학생 | 196명 · 반 7개(강사 6명 + 미배정) — 원장반이 첫 번째(도형우 원장) |
| 자습실 | 50석 · 벽면10 + A·B·C 각 12 + 안쪽4 · 덩이 사이는 **통로** |
| 학교 | 58곳 · 나이스로 101칸(중간52·기말49) 자동 채움 |
| 인스턴스 | 관제(도커) · 조회API(8197) · 키오스크(8195) 각각 별도 |
| 도메인 | DNS 없어 `dalseo.72-62-252-20.sslip.io` 임시(설정에 예정 주소 병기) |

**지점마다 다른 것을 설정으로 뺀 목록** — 반 구성·좌석 배치·모의고사 시간대·대기명단 문구
(대구는 '오픈자습실')·지점 이름·학교 지역·본사 지점코드. 화면 세 곳(관제 자습실 · TV 자습실 ·
아이패드 키오스크)이 **같은 `seatLayout` 하나**를 본다.

**본사 CRM은 그 지점 원장이 직접 넣는다.** 남의 학원 계정을 넘겨받는 게 부담이라는 문제 때문에,
관제 설정 화면에서 본인이 입력하면 암호화(Fernet·600) 저장하고 화면에 다시 안 보인다.
저장 즉시 본사에 로그인해 확인하고, 실패하면 알려 준다. OTP 시드는 지점 공통이라 공용 파일 하나로 둔다.
화면에 **"서버 관리자는 기술적으로 접근할 수 있다"**고 그대로 적었다 — 못 본다고 하면 거짓이 된다.

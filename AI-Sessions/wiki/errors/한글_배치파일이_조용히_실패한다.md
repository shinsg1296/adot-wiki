# 한글 배치파일이 조용히 실패한다 (+ 예약작업 검은 창)

## Summary

원장 PC 자동화의 배관(**작업 스케줄러 + `.cmd`**)에서 같은 뿌리의 고장 **4건**이 한꺼번에 드러났다. 공통점은 전부 **에러 없이 실패**했다는 것 — 성공 메시지는 그대로 찍히고, 로그 파일은 아예 안 생기고, 몇 달을 아무도 몰랐다.

## Details

### ① `.cmd` 안에 한글 + `chcp` = 파일이 통째로 깨진다

cmd.exe는 배치파일을 **그 순간의 코드페이지로** 읽는다. 파일은 CP949로 저장돼 있는데 안에서 `chcp 65001`을 하면, 그 뒤 줄들이 다른 코드페이지로 읽혀 **경로·명령·주석까지 깨진다.** `rem` 주석 한 줄이 명령으로 둔갑하기도 한다.

- 실측: `서버코드_복사.cmd`가 **2026-08-18부터 10-01까지 한 번도 복사하지 못했는데 "복사했습니다"만 찍혔다.** `_신고_옵시디언동기화.cmd`는 **생긴 이래 한 번도 성공한 적이 없었다**(로그 파일조차 없었다 — 고치자마자 신고 70건이 그제야 옮겨졌다).
- **고치는 법 — 둘 중 하나**
  - `.cmd`는 **ASCII 전용**으로 쓰고, 경로는 `%~dp0`(자기 폴더)로 잡는다.
  - 한글이 꼭 필요하면 PowerShell `.ps1`로 옮기고 `.cmd`는 그걸 부르기만 한다. ★`.ps1`을 **BOM 없이** 저장하면 PowerShell 5.1이 ANSI로 읽어 한글이 깨진다 — **UTF-8 BOM 필수**.
- ★**"지금 되니까 괜찮다"가 성립하지 않는다** — 같은 파일을 조금만 고쳐도 바이트 길이가 달라져 또 틀어진다. 실제로 멀쩡해 보이던 파일의 한 줄만 바꾼 시험본이 바로 깨졌다.

### ② 복사·동기화는 **결과를 확인**해야 한다

`copy /y ... >nul` 뒤에 무조건 성공 메시지를 찍으면 실패를 영원히 모른다.
- 새 판은 파일마다 **복사한 뒤 md5를 대조**해 `[갱신] / [같음] / [실패]`를 찍고, 하나라도 실패하면 **exit 1**로 멈춘다.
- 같은 원리: 배포한 뒤 **라이브 md5 = 로컬 md5** 확인.

### ③ 코드만 올리고 **데이터 파일은 멈춰 있었다**

VPS `/opt/adot-grade/_grade_exam_meta.json`(빠른채점 시험 → 학교·학년 메타)이 **2026-08-10에 멈춰 25개**였다. 로컬은 68개. 코드는 그동안 계속 배포됐지만 이 JSON은 배포 목록에 없었다.
- 증상: 2학기 시험이 **학교·학년 빈 값**으로 나와 분석지를 못 찾는다. **에러는 안 난다**(그냥 빈 문자열).
- → **배포 목록에는 코드뿐 아니라 그 코드가 읽는 데이터 파일도 넣는다.**

### ④ 예약작업을 `.cmd`로 걸면 10분마다 검은 창이 뜬다

작업 스케줄러 액션이 `.cmd`(또는 `python.exe`)면 실행될 때마다 콘솔 창이 화면을 덮는다. 10분 주기 둘 + 30분 하나라 원장이 계속 시달렸다("cmd창이 중간중간에 뜨는데 너무 번거롭다").

- **해법 = `C:\학생관리\_창없이실행.vbs`** — `wscript.exe`는 창이 없는 프로그램이라 **깜빡임조차 없다.**
  ```
  wscript.exe "C:\학생관리\_창없이실행.vbs" "실행할것.cmd" [인자...]
  ```
  속은 `WshShell.Run(명령, 0, True)` — **0=창 숨김**, **True=끝날 때까지 기다렸다 종료코드를 그대로 돌려준다**(작업 스케줄러의 '마지막 결과'가 살아 있다). VBS는 **UTF-16LE BOM**으로 저장한다.
- 작업의 **'숨김' 체크박스로는 안 된다** — 콘솔 창은 그것과 별개다.
- pythonw로 도는 서버가 **콘솔 프로그램**(python.exe·ffmpeg·netstat·taskkill)을 부를 때도 창이 뜬다 → `creationflags=CREATE_NO_WINDOW`(`0x08000000`). ★같은 파일이 리눅스에도 올라간다면 `0x08000000 if os.name == 'nt' else 0` 으로 둬야 한다(리눅스는 0이라 무해).

### 덤 — 중복 예약작업

`_신고_AI수리.cmd`(한글판)와 `ai_fix.cmd`(ASCII판)가 **같은 워커를 10분마다 두 번** 돌리고 있었다. 잠금 파일(`_ai_worker.lock`, 2시간)이 있어 실제 작업은 한 번만 됐다. **2026-10-01 원장 지시로 한글판 작업을 껐다**(삭제 아님 — 작업 스케줄러에서 「사용」으로 되살릴 수 있다). 남긴 쪽 = `HAWE_ReportAI` / `ai_fix.cmd`(실제로 일해 온 검증된 경로).

## 새 자동화 붙일 때 점검 목록

1. `.cmd`에 한글이 있나? → ASCII로 바꾸거나 `.ps1`(BOM 포함)로 옮긴다
2. 성공 메시지가 **실제 결과를 확인하고** 찍히나?
3. 로그 파일이 **진짜 생기나?** — 안 생겼다면 그 스크립트는 **한 번도 안 돈 것**이다
4. 작업 스케줄러 액션이 `.cmd`/`python.exe`인가? → `_창없이실행.vbs` 뒤로 보낸다
5. 그 코드가 읽는 **데이터 파일**도 배포 목록에 있나?

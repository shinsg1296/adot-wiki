# 디리스킹 장부 (검증됨 vs 미검증 · 리스크)

[[0_본사_전략실]] ③의 산출물. 실패한 방식·미검증 가정·재시도 금지 리스크를 모아 다음 사업 런칭 리스크를 줄인다. (실패 사례는 발생할 때마다 append.)

## 현재 열린 리스크 (미검증 / 미구현)

| 항목 | 리스크 | 상태 |
|---|---|---|
| 조정 기준표 수치 | 제안 단계(검증 전) | draft → [[교무부_운영룰]] |
| 진도 단일 출처 부재 | 진도가 원장 머릿속 → 이식·인수인계 불가 | 개선 과제 |
| 출결 시스템 | 현 CRM 종속 → 새 사업 자체 개발 필요 | 자체 키오스크로 **부분 해소**(등원·좌석·근태는 자체 보유). 단 결석 판정·수강등록은 여전히 본사 종속 → [[4_행정운영부]] |
| 자동화 백로그 7건 | 전부 미구현(설계만) | 백로그 |
| HAWE 전환 | 시점 미정·외부 노출 미정 | 보류 → [[브랜드_디자인_가이드]] |
| **백업이 같은 서버에만** | VPS 자체가 소실되면 백업도 함께 사라짐(오프사이트 없음) | 열림 — 주 1회 로컬 회수 미도입 |
| **관제 소스가 저장소에 없음** | 원장 PC와 VPS에만 존재. 둘 다 잃으면 재작성 | 열림 — private 저장소 이관 대기 |
| **본사 CRM 내부 주소 의존** | 공식 API가 아니라 화면 내부 주소를 빌려 씀 → 본사가 화면을 개편하면 조용히 깨짐 | 열림 → [[본사CRM_API_연동구조]] §5 |
| **빠른채점 성적 동명이인 미분리** | 성적이 이름 기준(`(name, cat)`)이라 동명이인 성적이 섞일 수 있음. 숙제·단어시험은 ID로 분리 완료 | 열림(실측 확인 2026-08-18) |

## 검증됨 (재사용 안전)

- 통화 자동기록 파이프라인(가동 중) · 수업일지 CRM 자동 알림톡(됨) · 레벨테스트 기준 · 정규 ABC·재시험 로직 · 모의/답지/exam_server 엔진.
- **관제 VPS 운영**(2026-08): 원장 PC 전원과 무관하게 동작 · HTTPS · 역할별 권한(서버측 데이터 필터) · 아이패드 출결 키오스크 · 조교 보드.
- **본사 CRM 읽기 연동**: 자동 로그인(OTP 자체 계산) + 캐시 + 세션 만료 자동 복구. 출결 3초·주간 출결·수강등록·강의수강 진도.
- **자동 복구·백업 체계**(2026-08-18): 5분 헬스체크(자동 재시작 + 디스코드 알림) · 정본 39개 매일 백업(복원 검증 포함).

## 실패 · 교훈 로그 (append-only)

### 2026-08-11 · 권한으로 거른 데이터가 원본을 덮어씀
조교 계정(당시 명단 0명)으로 관제를 열자 `pushSched()`가 **학생 0명을 VPS에 밀어** 자습실 '오늘 올 학생'과 출결이 전부 0명이 됐다. 로컬 정본으로 재push(70명) 복구.
**교훈: 권한으로 데이터를 걸렀으면, 그 데이터를 다른 곳에 쓰는 경로도 같이 막아야 한다.** → `canMirror()` 게이트. 상세 [[권한필터_파생데이터_덮어쓰기]]

### 2026-08-12 · 등원 이력 유실 (복구 불가)
VPS `_kiosk_history.json`에 8/10 이후만 남고 **7월 하순~8/9가 사라졌다. 백업이 없어 영구 유실.** 원인 추정=읽기 실패 시 `{}`를 그대로 저장하는 구조.
조치=매일 백업 + strict 가드(못 읽으면 저장 포기), 통계는 본사 CRM 등원기록으로 17일·369건 보충.
**교훈: 기록이 두 곳에 생기는 구조에서는 '한 곳이 비어도 덮어쓰지 않는다'가 먼저다.** 상세 [[기록이_두곳에_생기는_구조]]

### 2026-08-12 · 쓰기 타임아웃을 실패로 단정 → 중복 입력 유도
숙제 배정에서 **저장은 됐는데** 응답이 늦어 "배정 실패 — 다시 시도해 주세요"가 떴다. 그대로 다시 누르면 같은 숙제가 두 번 들어간다.
**교훈: 멱등하지 않은 쓰기는 타임아웃돼도 실패로 단정하지 않는다. 서버를 재조회해 확인한 뒤에 실패를 말한다.**

### 2026-08-13~14 · 같은 데이터를 두 키로 조회 (동명이인)
카드는 이름으로, 모달은 `이름|ID`로 조회해 **동명이인 김민성의 숙제가 한쪽엔 남의 것이 붙고 한쪽엔 안 보였다.** 동명이인 목록 자체도 두 벌이었다.
**교훈: 키 표현은 한 곳에서 만든다. 목록 정의가 두 벌이면 그것부터 합친다.**

### 2026-08-14 · '해당 없음'을 0으로 반환 → 임계값 0에서 전원 통과
자습실 미등원 경고에서 대상 아님을 `0`으로 돌려주다가, 유예를 5분→0으로 바꾸자 **하원 완료·본사 결석까지 17명 전원이 빨간 경고**로 떴다.
**교훈: 센티널을 유효 범위 안의 값으로 표현하지 않는다(-1·null). 임계값을 바꿀 땐 그 값을 비교하는 모든 분기를 함께 본다.**

### 2026-08-14 · '완료 → 원상복귀'의 복귀 시점 오류
미리 당겨 수업한 학생이 **같은 주 원래 요일에 다시 나타났다**(그 주 수업은 이미 소진됐는데도).
**교훈: 자동 복귀는 '언제' 복귀하는지를 명시한다. 주 단위 배치에서 그 주 안의 복귀는 "한 번 더 오라"는 뜻이 된다.**

### 2026-08-14 · 분할 조회가 조용히 일부를 누락
본사 학생 코드를 **담당 선생님별로 나눠** 받았는데, 선생님 목록 API가 403이라 원장 담당 44명만 들어가고 **정국쌤반 22명이 통째로 빠졌다**(강채원 "코드 못 찾음"). 실제로는 조건 하나(`sort=not_set`)만 맞추면 지점 전체 66명이 한 번에 나온다.
**교훈: 분할 조회는 "합치면 전체"가 보장될 때만 쓴다. 전체 수를 아는 다른 경로로 대조한다.**

### 2026-08-18 · 감시·백업 공백 (사고 전 해소)
점검 결과 **서비스가 죽어도 알려주는 장치가 전혀 없었고**(cron은 백업·계정잠금뿐), 백업은 등원기록 1종뿐이라 프로필·근무표·근태·계정·정답키는 유실 시 복구 수단이 없었다.
조치=5분 헬스체크(응답까지 확인·자동 재시작·1시간 3회 제한·디스코드 알림) + 정본 39개 매일 백업(복원 검증 포함).
**교훈: 사고가 난 데이터만 백업하면 다음 사고는 다른 파일에서 난다. 백업은 '복원해봤는가'까지가 한 세트다.**

# 자동검증 오판 — 텍스트만 믿지 말고 원본 확인

## Summary

자동 검사·분석가가 "문제 있음/없음"을 **추출 텍스트나 음성 인식 결과만으로** 판정해 틀린 사례 모음. 공통 교훈: **판정 전 원본(이미지·음원)을 직접 확인**하고, 멈춘 자동화는 원인이 오탐인지 진짜 결함인지 가른다.

## Details

1. **서킷 22·23회 듣기 미반영(9/29)** — 매일 18시 자동화가 둘 다 15/16으로 업로드 보류, 로그엔 "정답키만". 22회=whisper가 "2번"을 **"이번"**으로 적은 오탐(클립 정상) → `_listen_verify.py`에 한글 수사(이번·삼번…) 인정 추가. 23회=1번 클립이 발문 없이 대화 중간부터(**진짜 오류**) → `_listen_fix_q1.py`로 재절단 16/16 → 업로드·배포 v64. ★로그에 "정답키만"이 보이면 음원 미반영.
2. **최파 17회 44번 "정답 없음" 오판(9/30)** — 분석가가 텍스트로 "(d) her friend=Mina"라 판단. 원본 이미지: 밑줄이 **her 한 단어**(Jiyun 소유격) → 정답 ④ 정상. 지칭 문항은 밑줄 범위를 이미지로 확인.
3. **분석가 간 채점 감각 편차** — 같은 기준·보정 사례를 줘도 담당별 50%↑ 문항 수 평균 6.1 vs 3.8. 여러 분석가 결과를 합칠 땐 표본 교차 판정 필요.
4. **한글(HWP) COM 자동화** — `Hwp()`가 원장이 열어 둔 한글 창에 붙어 문서에 글자를 넣은 사고 → **항상 `Hwp(new=True, visible=False)`**, 원장 한글 강제 종료 금지. 한글이 안 켜진 원인은 **VC++ 2013 x86 런타임(MSVCP120) 누락**. HWPX 스타일 ID는 샘플 최대 ID 뒤에 연속으로(100부터 쓰면 무시됨), 줄간격 FIXED는 겹침→PERCENT, HWPX 문단 여백·탭 위치는 **절반으로 읽힘**(2배로 넣어야 함), 사각형 도형 numberingType="FIGURE"는 열기 hang → "PICTURE". hang 난 COM 한글은 권한상 강제종료 불가 → 원장이 작업관리자에서 정리.
5. **서킷 22회 '수능 양식' 재조판** — 웹(HTML) 재조판 2안은 원장이 폰트·형태 모두 거부("진심 이게 비슷하다고 생각하고 주는거야"). 수능 폰트는 HWP 전용(HFT) → 한글 HWPX로 재구성했으나(수능 실측 치수 일치) 10쪽·원장 "너는 안되겠다"로 GPT 방식 대기. 재시도 시 원장이 보여 줄 GPT 결과·프롬프트부터 확인할 것.

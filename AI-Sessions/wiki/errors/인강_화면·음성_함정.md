# 인강 화면·음성 함정 (교재 전용 인강)

## Summary

문법 검사·빌드는 전부 통과하는데 **화면에서만, 소리로만** 드러나는 사고들. 새 화면이나 새 대사를 만들 때 이 목록을 먼저 본다.

## Details

### 1. 흰 종이 위에 흰 글자 (밝은 테마)
새로 만든 판서 칸의 글자색을 어두운 테마 기준(`#E4E9F2`)으로 박아 뒀더니, 밝은 '책 느낌' 테마에서 **해설이 거의 안 보였다**(원장 지적 "이거 해설 거의 안 보이는데?"). 테마는 정해진 색표만 치환하므로 표에 없는 색은 그대로 남는다.
→ **규칙**: 새 화면의 글자색은 `color:inherit`(테마가 관리하는 색을 물려받게). 색을 꼭 줘야 하면 테마 마감 CSS에 밝은 테마 예외를 같이 넣는다.
→ **검수법**: 화면을 순회하며 **조상의 반투명 배경까지 합성한 실제 배경**으로 대비(WCAG)를 계산한다. 무대 배경만 기준으로 잡으면 배지 위 흰 글자가 전부 오탐으로 잡힌다(44건 중 진짜는 1건이었다).

### 2. 정규식 역참조가 제어문자로 바뀜 → 정답 단어가 통째로 사라짐
패치 스크립트를 거치며 `\1`이 **제어문자 0x01**이 되어, 교재 필기 칸의 정답 단어가 전부 빈칸으로 나왔다(화면엔 조사만 남음). 같은 사고를 이틀에 두 번 냈다.
→ **규칙**: 역슬래시+숫자는 중간 스크립트를 거치지 말고 파일에 직접 넣는다. 고친 뒤 바이트로 확인한다. 조립기에 게이트를 박아 두었다(제어문자가 섞이면 빌드 중단).

### 3. TTS가 한국어 문장 속 영어 낱말을 못 읽는다
- `it` → 아예 빼먹거나("이 보이면"), 문장 맨 앞 '잇이'를 **"이십오"**로 읽음
- 심지어 **"13번"을 "14번"으로** 오독
- 문장 뒤에 **영어 광고 문구·영어 문장을 멋대로 덧붙임**("This time, I'm going…")
→ **규칙**: 음성 대본에서 영어 낱말을 문장 맨 앞에 두지 말고, 위치를 옮기거나 우리말로 바꾼다(화면 표기는 영어 그대로 둔다). 대사에 원문자(①②③)도 금지(오독).
→ **장치**: 받아쓰기 검사가 녹음마다 대본과 대조해 최대 4회 재녹음한다. 기록은 `gen/_tts_cache/gemini_asr/*/*.json`의 text·heard·reason으로 확인.

### 4. 인라인 style이 CSS 격자를 덮어쓴다
본문 화면을 2단 격자로 바꿨는데 적용이 안 됐다. 원인은 화면 전환 코드가 `display:flex`를 **인라인으로** 박고 있었던 것.
→ 보일 때는 인라인 값을 **지우고**(removeProperty) CSS가 결정하게 한다.

### 5. 자동 넘김 타이머를 멈추는 경로가 하나뿐이었다
문제를 맞히면 자동으로 다음으로 넘어가게 만들었더니, **일시정지·스페이스바·5초 되감기로는 그 예약이 안 끊겼다**. 멈춰 놓은 강의가 혼자 넘어가고 재생까지 다시 켜졌다. 채점 뒤 '이어보기'를 누르면 화면을 다시 그려 **채점 결과가 통째로 날아가기도** 했다.
→ 타이머를 거는 기능을 만들면 **끊는 경로를 전부**(버튼·키보드·되감기) 같이 만든다. 되돌리기 힘든 화면은 다시 그리지 말고 상태를 지킨다.
→ 이 5건은 공용 파일을 고친 뒤 **다각도 회귀 검토를 돌려서** 찾았다(원장 지적 전에 발견).

### 6. 설계 데이터가 답을 흘린다
직접 쓰기 문제의 단어 칩이 **정답 순서 그대로** 배열돼 있어, 읽지 않고 위에서부터 끼우기만 해도 만점이었다(원장 지적 "보기가 순서대로 배열되어 있는데?").
→ 보기·칩·선지는 **만들 때 섞는다**(빌드마다 같은 순서가 되도록 고정). 설계 JSON을 그대로 화면에 쓰기 전에 "이 배열이 답을 알려 주지 않는가"를 본다.

### 7. 도구 환경
`ffmpeg` 호출이 **Bash 도구에서만 WinError 5(액세스 거부)** 로 막혔다. 같은 명령을 PowerShell 도구로 돌리면 통과한다.

# 분석지 수리는 생성물만 고치면 사라진다 — 정본이 4단계 위에 있다

## Summary

원장이 시험지 분석 화면을 전수 점검해 찾은 **결함 21건**을 신고함 AI 수리에 일괄로 맡겨 **19건을 고쳤다**(2건은 자료가 없어 AI가 거부 — 정상 동작). 그런데 AI 워커는 **라이브 파일을 떠 와서 고치고 되올리는** 방식이라, 고친 자리가 빌드 사슬의 **맨 끝 생성물**이었다.

**시험 하나만 더 분석해서 `_finish_exam.py`를 돌리면 19건이 전부 조용히 날아간다.** 경고도, 백업도 없다.

분석지를 고칠 때는 **고친 파일이 정본인지 생성물인지 먼저 확인**한다. 이건 [[권한필터_파생데이터_덮어쓰기]]·[[기록이_두곳에_생기는_구조]]와 같은 뿌리의 세 번째 사례다.

## Context

- **언제**: 2026-09-30 밤~10-01 새벽. 원장 지시 "지금 리포트에 있는거 전부 고치고 반영 다시 해줘".
- **어떻게 드러났나**: 다음 요청("발문에 구절 있는 것들 자동으로 그어줘")을 처리하려면 **빌드가 필요**한데, 빌드하면 방금 고친 19건이 사라진다는 걸 사슬을 추적하다 발견했다. 원장이 물어서 안 게 아니라, 고치기 **전에** 사슬을 확인해서 잡았다.
- **왜 생겼나**: AI 수리 워커는 앱마다 `root`(작업 폴더)를 정해 두는데, 관제 앱의 `root`가 **배포본**(`/opt/adot-dash`)이다. 관제 화면 대부분은 배포본이 곧 정본이라 맞지만, **`/analysis/index.html`만 예외**로 4단계 빌드의 산출물이었다.

## Details

### 빌드 사슬 — 어디가 정본인가

```
[정본]  web/index.html                         ← 렌더 코드(renderExam·마커·레이아웃)
[정본]  _extra_exams.json                      ← 경신여고1 · 동신여고1(고1 공통영어1) 2건 전용
[정본]  _<키>_analysis.json + _<키>_ocr/p*.json ← 그 외 대부분의 시험 자료
[정본]  _build_web_data.py                      ← 시험 등록 목록 · 메타 · 표시 정리 로직
[정본]  web/data.js.bak_pre_multi               ← 최초 동신고1 1차 시드(삭제 금지)
           │
           ▼  _build_web_data.py   (data.js를 'w' 모드로 통째 재작성 · 백업 안 남김)
[생성물] web/data.js                            ★손으로 고치면 안 된다
           │
           ▼  _build_ilgok_html.py / _build_wirye_html.py
[생성물] web/일곡점_분석.html · 위례점_분석.html
           │
           ▼  _build_kwanje_analysis.py
[생성물] web/_kwanje/일곡점.html · 위례점.html
           │
           ▼  scp
[생성물] VPS /opt/adot-dash/analysis/index.html   ← ★AI가 고친 곳
        VPS /opt/adot-dash-wirye/analysis/index.html
```

`_finish_exam.py`(시험 1개 마무리 원클릭)가 **①빌더에 등록블록 자동 삽입 → ②`_build_web_data.py` 실행 → ③QA → ④HTML 빌드**를 한 번에 돈다. 즉 **시험 하나 추가 = data.js 전체 재생성**이 정규 워크플로다.

### 이번에 고친 것 — 다음 빌드 전에 정본으로 옮겨야 하는 목록

**렌더 코드 5가지** → `web/index.html`로 역포팅

| 고친 것 | 내용 |
|---|---|
| `blankLabels()` 신설 | 발문에 적힌 빈칸 표지(ⓐⓑ…)를 지문 빈칸에 순서대로 얹음. **'빈칸' 뒤의 표지만, 개수가 딱 맞을 때만** — 밑줄 표지(ⓐ~ⓔ)나 순서 (A)(B)에 잘못 붙느니 비워 둔다(원장 2026-09-30) |
| `.blk.lb` CSS | 빈칸 안 표지 글자 |
| 각주 분리 | 각주(`*어휘 뜻풀이`)는 **조건이 아니다** → 조건에서 떼어내 맨 아래 따로 |
| 보기/조건 분리 | 보기 단어목록 뒤에 `<조건>`이 한 줄로 붙어 오면 잘라 다음 줄로(조건이 보기 칩 안으로 통째로 들어가던 문제) |
| `renderExam(text, ask)` | 발문 배열을 넘김. 세트 공통지문은 구성 문항들의 발문을 모두 넘김 |

**자료 17문항** → 동신여고2 영어Ⅱ(2학기 1차)의 `출처`. `수특Light독해 02강` → `수특Light독해 02강 Ex03`처럼 **교재 안 문항번호까지** 붙였다. 대상 = 1·5·7·8·10·11·12·17·18·19·20·24·25·26·서술1·서술2·서술4.

### 같이 드러난 취약점 3가지 (아직 안 고침)

1. **`_extra_exams.json`이 사라지면 2건이 말없이 증발한다.** `_build_web_data.py`가 `except FileNotFoundError: pass`로 넘어가므로 경신여고1·동신여고1이 경고 없이 data.js에서 빠진다. 이 두 시험은 다른 백업 사본이 없다.
2. **옛 빌더가 아직 현행 data.js를 가리킨다.** `build_bank.py`(구 스키마 `window.__EXAM=` 단일 시험)와 `_bak_bank_20260920/_build_web_data.pre_bonsa*.py` 2개. 실수로 실행하면 현행 42건이 파괴된다.
3. **`examcheck_server.py` `/save_to_viewer`로 넣은 시험은 재빌드에 유실된다.** 빌더에 등록되지 않기 때문. 경신여고1·동신여고1이 `_extra_exams.json`으로 따로 떠 있는 이유가 바로 이것.

### 재발 방지 — 분석지를 고칠 때 지킬 것

- **고치기 전에 그 파일이 생성물인지 확인한다.** 파일 첫머리 주석·`_build_*.py`가 그 경로에 쓰는지 grep 한 번. 관제 화면이라고 다 정본이 아니다.
- **AI 수리에 맡길 때도 마찬가지.** 관제 앱 `root`가 배포본이라 `/analysis/` 아래는 자동으로 생성물을 고치게 된다. 이 경로는 사람이 정본에서 고치고 빌드하는 편이 낫다.
- **역포팅 전에는 빌드를 돌리지 않는다.** 빌드가 필요하면 먼저 라이브와 마지막 빌드본을 diff 떠서 "AI/사람이 생성물에만 넣은 변경"을 뽑아낸다(3자 비교 — 빌드본 vs data.js vs 라이브. data.js가 빌드본보다 최신일 수 있어 2자 비교는 오판한다).
- **생성물에 직접 넣은 수정은 그 자리에서 정본에도 넣는다.** 미루면 이번처럼 사슬을 역추적해야 한다.

### 운영에서 배운 것 (신고 일괄 처리)

- **같은 성격의 신고는 묶어서 먼저 보낸다.** 관제 앱은 작업 직전 라이브를 다시 떠 오므로, '밑줄 빠짐' 9건을 먼저 보내면 앞 건이 고쳐 놓은 걸 뒤 건이 '이미 고쳐져 있음'으로 금방 끝낸다. 반대로 하면 같은 곳을 여러 번 고친다.
- **AI가 "자료가 없어 못 고치겠다"고 거부하면 그게 정답이다.** 이번 2건(요약문 누락)은 시험지 원문이 없으면 지어내는 수밖에 없는 건이라 거부가 옳다. 다시 맡겨도 같은 답이 나오니 **사람이 원문을 넣어 주는 것**이 유일한 해결이다. → [[SOP_내신분석지_제작법칙]] §2 "원문은 절대 지어내지 않는다"

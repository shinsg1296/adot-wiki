# 설계도 조립 엔진 (변형문항 생성 3세대)

## Summary

**AI는 지문을 쓰지 않는다.** AI는 **설계도(JSON)** 만 쓴다 — 몇 번째 문장에 마커를 걸지, 어떤 문장을 새로 끼울지, 어떤 낱말을 틀린 형태로 바꿀지, 선지·정답·해설. **지문은 프로그램이 원문 문장 배열에서 조립**한다. 그래서 원문 훼손이 **구조적으로 불가능**하다.

2026-07까지 반복된 고질병(지문 오염·가짜 변형·정답 쏠림·해설 stale·순서 깨짐)을 한 번에 없앤 방식. 2026-09 이 방식으로 **메가 390 + 수특L 206 = 596문항** 제작 → 블라인드 재풀이 전량 정답 일치 · 게이트 HARD 0 · 재빌드 소실 0 · 정답 번호 사후 변경 0.

## Context

- **1세대** `_hawe_q_workflow.js`(제목 전용) → **2세대** `_hq5_workflow.js`(10유형, **AI가 지문을 통째로 출력**). 2세대에서 반복된 결함과 그 대응 이력 = [[하위큐_문제생성_시스템]] 2026-07-04·2026-07-31 절.
- 2세대에서도 **순서 유형만은** 이미 결정론 조립이었다(`_seq_gen`: 조립 후 합본==원문 검증). 원장 기준도 "순서문제는 AI 통째생성 금지".
- **3세대 = 그 원칙을 10유형 전부로 확대한 것.** 순서만 안전하던 구조를 전 유형으로 넓혔다고 보면 된다.

## Details

### 왜 훼손이 불가능한가

설계도에는 **지문 문자열이 없다.** 있는 것은 좌표와 부품뿐이다.

| 필드 | 뜻 |
|---|---|
| `s` | 원문 문장 번호(1-base) — 마커·빈칸·밑줄을 걸 자리 |
| `new` | 새로 끼울 문장(무관 유형에서만. 원문에 없던 문장) |
| `insert_after` | 그 문장을 몇 번째 뒤에 넣을지 |
| `wrong` | 틀린 형태(어법·어휘에서 바꿀 낱말) |
| `choices`·`ans`·`expl` | 선지·정답·해설 |

조립기 `render(key, t, pl)`가 `passages_*.json`의 `sents`(문장 배열)를 읽어 지문을 만든다. **AI가 원문을 다시 타이핑할 기회 자체가 없다.** 추출 단계에서 한 번만 정확하면 끝까지 안전하다.

### 엔진 구성 — 새 교재 하나 추가에 필요한 것

정본 라이브러리 = `C:\하위큐웹\_mega_gen\_mega6910_lib.py`. 환경변수 **`HQ_PLAN_CFG`**(JSON: `base`·`passages`·`targets`·`gen` 경로)로 교재를 갈아끼운다. 새 교재는 아래 5개만 복제한다.

| 파일 | 역할 |
|---|---|
| `plan_cfg.json` | 경로 설정 — **★슬래시 경로로 쓸 것**(역슬래시는 JSON 이스케이프 사고) |
| `_check_*.py` | runpy 래퍼 — 설계도 형식·정답·해설 **전수 검사** |
| `_targets_*.py` | 정답 배정표 생성(지문×유형 → 목표 정답번호) |
| `_*_build.py` | 설계도 → 문항 조립 → `_FINAL_*_items.json` |
| `_*_blind.py` | 정답 가린 문제지(`sheets`) 생성 / 채점(`compare`) |

추출기 `_*_extract.py`는 교재 형식마다 다르므로 공용화하지 않는다.

### 제작 순서

1. **추출** PDF·docx → `passages_*.json`(`sents` = 문장 배열)
2. **배정** `_targets_*.py` → `_targets_*.json`. **★한 번 만든 배정표는 다시 만들지 않는다** — 이미 쓴 설계도의 정답과 어긋난다
3. **설계도** 지문 6개씩 서브에이전트에 배분, 지침 `_PROMPT_*.md` 읽히고 `gen/q_<key>.json` 쓰게 한다
4. **검사** `_check_*.py --all` — ✗인 지문만 재작업
5. **조립** `_*_build.py` → `_FINAL_*_items.json`
6. **블라인드** `_*_blind.py sheets N` → 별도 에이전트가 `solve/sheet_N.md` 풀기 → `compare`
7. **병합** 부교재는 `_hawe_q_bank.py`가 `_FINAL_*`를 직접 병합 / **모의고사는 `_hawe_q5.json` 경유**(`_mock_to_q5.py <FINAL> --apply`) — 뱅크 빌더가 q5를 읽기 때문
8. **게이트** `_qa_gate.py`(HARD 0) → **배포는 원장 허락 후**

### 구조 규칙 — 유형 적합성은 원문 문장 수가 결정한다

| 유형 | 최소 문장 |
|---|---|
| 어휘·삽입 | 6문장 (삽입은 본문 5 + 주어진 문장 1) |
| 무관·어법 | 5문장 |
| 순서 | 4문장 (나열형 글은 skip) |

- **6문장 지문에 삽입 ⑤는 배정 불가** — 마지막 슬롯이 남지 않는다. 배정표에서 다른 지문과 맞바꾼다.
- **무관 ⑤는 마지막 문장이어야 한다** — 기존 뱅크 95%가 그렇다. ⑤ 뒤에 문장이 남으면 검사기가 오류로 잡는다(메가에서 27건 색출·재작업: 자리 이동 22 + 번호만 변경 5).
- **무관 문장을 인용문(따옴표) 안에 넣지 않는다** — 화자 발화가 끊긴다(블라인드가 메가 6과-7 지적).
- **NARR(20문장↑ 이야기 글 = 모의 43~45)** → 주제·요약·빈칸·무관 제외. 어휘·어법·순서·삽입만.
- **skip은 정상 동작.** 못 만드는 유형은 억지로 만들지 않는다(어휘 6문장 미만·함의추론 비유구 없음 등).

### 정답 균형 — 사후 재배치가 아니라 **사전 배정**

2세대는 만든 뒤 재배치했고, 그래서 해설이 옛 번호를 참조하는 **stale 버그**가 반복됐다. 3세대는 **목표 정답을 먼저 정해 설계도에 주므로 재배치 자체가 없다.**

- 어휘·순서 ①은 5% 수준 · 무관은 ②③④ 중심 · **삽입 ①은 쓰지 않는다**
- 같은 번호 **연속 금지 · 한 칸 건너 반복 금지**(무관·삽입은 연속 금지만)
- 한 지문 안에서 같은 번호 **≤3**
- 실측(메가 390): 정답 번호 사후 변경 **0건**, 삽입 ① **0건**

### 블라인드 풀이 검증

정답·해설을 가린 문제지(`solve/sheet_N.md`)를 만들어 **설계도를 안 본 다른 에이전트**가 풀고(`ans_N.json`), `compare`로 대조한다. **정답표는 세션 임시폴더에 둬** 문제지와 섞이지 않게 한다.
이 단계가 실제로 잡은 것: 콜론 문장이 두 문장으로 쪼개진 오류(메가 10과-22), 무관 문장이 인용문 안(6과-7), 한 번호에 두 문장(수특 04강-4 → 추출기 `SPLIT_AFTER` 규칙으로 분리).

# 관제 저장소 이관 절차

[[디리스킹_장부]] 열린 리스크 **"관제 소스가 저장소에 없음"** 을 닫기 위한 절차.
현재 관제는 **원장 PC(`C:\학생관리\dashboard\`)와 VPS(`/opt/adot-dash/`)에만** 존재한다.

⚠️ **이 폴더의 파일은 원장님 PC 또는 VPS에서 직접 실행해야 한다.** 관제 소스는 이 위키 저장소에 없다.

## 왜 화이트리스트인가

관제 폴더에는 **코드와 데이터가 같은 자리에 섞여 있다.** 그냥 `git add -A` 하면 이런 것들이 함께 올라간다:

| 올라가면 안 되는 것 | 왜 |
|---|---|
| `_관제_계정_비밀번호.txt` | 전 직원 평문 비밀번호 |
| `_contacts.json` | 학생·학부모 연락처 172명 |
| `profiles.json` · `roster.js` | 학생 프로필·명단 |
| `_crm_passwd.txt` · `token.json` | 본사 CRM 인증 |
| `branch.json` | 지점 시트 주소·토큰 |
| `ux.json` · `books.json` · `textbooks.json` | **이름은 설정, 내용은 학생 데이터** (2026-08-20 대구달서점 사고) |

마지막 줄이 핵심이다. [[지점_복제할때_데이터가_따라간다]]의 교훈 그대로 —
**"이름이 설정 같아도 안에 학생 이름이 있으면 데이터다."**
위험한 것만 나열하는 블랙리스트는 반드시 하나를 놓친다. 그래서 **전부 막고 코드만 연다.**

> **한 번 커밋하면 지워도 히스토리에 남는다.** 실수하면 저장소를 새로 파는 게 빠르다.
> 그래서 아래 3단계는 순서를 지켜야 한다.

## 절차

### 1. 준비 — 파일 두 개를 관제 폴더로 복사

```bash
# 관제 폴더에서
cp <이 폴더>/gitignore_관제 .gitignore
cp <이 폴더>/민감정보_스캔.py .
```

### 2. 스테이징 — 아직 커밋하지 않는다

```bash
git init
git add -A
git status --short          # ← 여기 뜨는 것만 올라간다. 눈으로 한 번 훑는다.
```

**`git status`에 데이터 파일이 하나라도 보이면 멈춘다.** `.gitignore`에 추가하고 `git add -A`를 다시 한다.

### 3. 스캔 — 통과해야 커밋

```bash
python3 민감정보_스캔.py
```

- **종료코드 0** → 커밋해도 된다
- **종료코드 1** → 잡힌 파일을 `.gitignore`에 넣고 `git rm --cached <파일>` 후 2번부터 다시

스캐너가 보는 것: 휴대폰 번호 · 주민번호 형태 · 비밀번호 대입 · API 키/토큰 · 구글 시트 ID ·
개인 키 · 절대경로 · **따옴표로 감싼 한글 이름 30개 이상**(명단·프로필 탐지).

### 4. 커밋 · 저장소 연결

```bash
git commit -m "관제 소스 최초 등록"
git remote add origin https://github.com/shinsg1296/<저장소이름>.git
git branch -M main
git push -u origin main
```

⚠️ **반드시 private 저장소여야 한다.** 코드에 학원 운영 로직·본사 CRM 경로가 들어 있다.

### 5. VPS 쪽도 대조

원장 PC와 VPS의 코드가 갈라져 있을 수 있다([[기록이_두곳에_생기는_구조]] — 8/10 이전 때
정답키 로컬 파일만 그 시점에서 멈췄던 것과 같은 구조).

```bash
# 두 곳의 코드 파일 해시를 비교해, 어느 쪽이 정본인지 먼저 정한다
md5sum *.py *.html *.js | sort
```

**정본을 정한 뒤에 커밋한다.** 어느 쪽이 최신인지 모른 채로 올리면 저장소가 틀린 정본이 된다.

## 이관 후

- 디리스킹 장부의 **"관제 소스가 저장소에 없음"** 을 닫는다
- 배포 흐름은 [[하위보카]](`shinsg1296/adot-word-app`)와 동일하게 git push 기준으로 맞춘다
- `.gitignore`에 열려 있지 않은 새 파일을 올리려면 규칙을 직접 추가해야 한다 —
  그때마다 "이건 코드인가 데이터인가"를 한 번 생각하게 되는 것이 이 방식의 목적이다
